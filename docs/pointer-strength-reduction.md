# 指针归纳变量与机器窥孔优化

## 原理与 IR 层

[LLVM LoopStrengthReduce](https://llvm.org/doxygen/LoopStrengthReduce_8cpp_source.html)
把循环内地址表达式表示为递推，选择时同时考虑指令、寄存器、步幅、初始化和寻址成本。
[IndVarSimplify](https://llvm.org/doxygen/IndVarSimplify_8cpp_source.html)
进一步处理等价归纳变量与退出条件。Sakura 在 `mem2reg` 和 CF LICM 之后的
`ind-var` pass 实现这些变换：平坦 CF 层已经具有 SSA Phi、明确回边和支配关系，
适合检查 `continue` 的所有更新路径。结构化层仍负责循环变换和展开。

对于 `gep(base, i*K+J+C)`，同一循环中相邻位移共享一个指针 Phi。
位移聚类适配 RV64 的 12 位有符号 load/store 立即数，每个循环至多新增四个递推。
相同初始化、且每条回边步长相同的整数 Phi 可以合并。常量种子的同步计数器
还可按 `j=q*i+c` 在地址分析中统一，前提是每条回边都满足同一关系；
只有步长相同而控制路径不同的计数器不能共享。

如果整数 IV 的活跃用途只剩更新和退出判断，已有指针可以承担终止判断：

```text
i = phi(init, i+step)           p = phi(base+init*K+J, p+step*K)
while (i < bound):      =>     while (p != end):
  use(base+i*K+J)                use(p)
```

常量界限把 end 舍入到第一次不满足原比较的迭代值，处理非单位步长和倒序循环。
运行时单位步长需夹住空域端点。指针使用相等/不等判断，避免假设对象地址的
有符号顺序。最终 IV、更新值、调用实参或其它数据用途仍可观察时，保留整数递推。
最后通过从可观察指令追溯的活跃标记删除无用 Phi/更新环，而非仅依赖零引用 DCE。

## 合法性

IR 的整数地址偏移是 i32，GEP 将它符号扩展后与 64 位地址相加。
循环中的 `i*K+J` 回绕时，64 位指针累加不能自动复现同一地址。
共享的 `RangeAnalysis` 同时服务中端与指令选择，证明循环计数器更新、
完整偏移、退出端点和字节步幅不发生有符号回绕。证明失败时使用 i32 字节偏移
Phi 与 word 更新，仍在每次访问处符号扩展后加上对象基址。相邻位移也先按
i32 相加，不直接折入 64 位指针。这种后备形式保留回绕语义，同时移走循环内乘法，
相同步幅和偏移的不同对象还可共享一个偏移递推。
该后备形式只用于直接内存访问；仅作为内部循环行基址的非叶子 GEP 不新增
偏移递推，避免把每轮计算一次的值变成跨整个循环存活的额外寄存器。
若所有实际访问都可能被 `continue` 等路径跳过，也不新增后备偏移递推：
这种形式在访问点仍需基址加法，跳过访问的迭代却多了递推更新和存活寄存器。
没有执行频率时，要求组内至少一个实际访问支配所有回边，保守估计收益。
分析采用有界迭代与保守区间，支持常量界限、受守卫约束的单位递推、负系数及 Select。
另可使用实际内存访问证明：对象小于 2^31 字节、字节步幅可表示为 i32，且一个
实际访问的锚点支配每条回边时，偏移回绕会使相邻两次访问相差至少 2^31 字节，
它们不可能都位于该对象内。此证明仅服务实际 Load/Store，不能用于逃逸地址或
指针退出条件，也不使用未实际访问的位移作为锚点。未知对象仍采用 modular offset。
数组参数的对象上界来自封闭程序中所有直接调用点，任何未知实参都会阻止推导；
递归中无法建立的事实保守放弃。
非线性表达式、不一致回边和不满足支配关系的循环保持原状。

## 窥孔与复制

[LLVM PeepholeOptimizer](https://llvm.org/doxygen/PeepholeOptimizer_8cpp_source.html)
也在机器层处理复制与寄存器类约束。这里优先在分配前传播块内复制，
跟踪源的重定义以及 Phi 副本的非 SSA 定义；不把复制关系跨块传播。
局部传播只选择用途局限于本块、定义唯一的目标，随后清理死复制，
避免把两个独立存活区间延伸到后继。寄存器分配后的清理仍检查物理寄存器文件。

`la s0,data; mv a0,s0; mv a2,a0` 可在定义和活跃性允许时合成直接使用。
若 s0 的值还需在调用后使用，其保存与传参复制仍由活跃性和 ABI 决定。
`slliw ...,i,2; addiw ...,-4` 可以复用已有 `i-1` 的缩放，省去重复加法。
只有匹配到已有表达式时才重写，不为形式上的合并新增长期存活的临时变量。

[RV64I 规范](https://docs.riscv.org/reference/isa/unpriv/rv64.html)明确 word 指令
产生符号扩展的 32 位结果，因此这些算术恒等式按模 2^32 推导。
`addiw d,wide,0` 是符号扩展，只有输入已被证明为规范 i32 或操作为指针加法时，
才能按零加法改成复制。不能把 word 缩放/偏移直接当成任意 64 位地址加法。

地址共享还会影响冗余 store 的匹配。把一个 Load 的值写回相同地址，只有在
Load 到 Store 之间没有可能改变该位置的写入时才是冗余；别名 store、调用和
带内存效果的结构化区域都会阻止删除。跨块 Load 也不能仅凭指针身份建立
局部证明。完全相同地址上写回同一 SSA 值可以保留这项事实。
两个明确且不同的 Alloca/Global 对象可以证明互不别名；指针 Phi 等未知根
仍可能指向本函数的栈对象，不能因为其中一方是 Alloca 就判为不相交。

## 验证与诊断

独立 IR 解释器比较内存地址、迭代次数、最终 IV，覆盖同步及不同步回边、
倒序、空域、非单位步长、偏移回绕、未知步幅与可观察值。机器指令解释器
覆盖复制链、源重定义、重复优化、word 极值和 64 位输入符号扩展。
独立内存解释器检查别名 store、调用、跨块恢复和纯计算之间的 Load 写回，
在修复前能复现冗余 store pass 的错误删除，修复后保持内存结果。
源级样例用 GCC 独立生成预期结果，再与 LLVM 和本编译器在 RISC-V 上比较。
`cases/regression/store_back_alias.sy` 还通过两次数组输入制造内存修改，再恢复
保存值并从运行库调用观察数组，避免只检查已被 SSA 转发的标量值。

`--pass-stats` 的 `backend-ra` 给出整数/浮点活跃峰值、跨调用活跃值、
spill 槽、spill 读写和保存寄存器数量。`tools/benchmark/register_pressure.py`
按函数配对比较它们。序言中的 callee-saved 保存不是变量 spill；静态 spill
数量也不是动态执行次数。计时需要重复 A/B，QEMU 的结果不能推导硬件分支预测命中率。
对比数据放在 [results](../results/pointer-strength-reduction/)，完整执行产物放在 build。

`SAKU_NO_INDVAR` 关闭整个中端变换；`SAKU_NO_IV_REUSE`、`SAKU_NO_PTR_END`、
`SAKU_NO_COPY_PROP`、`SAKU_NO_SCALE_REUSE` 分别隔离计数器共享、退出条件、
复制传播和缩放偏移复用，便于定位正确性与压力回退。
`SAKU_NO_OFFSET_IV` 单独关闭保持回绕语义的偏移后备变换。
